Most “slow database” horror stories end the same way: a missing index. Here is how to think about indexing correctly.

B-tree basics

An index is a sorted structure that lets the engine find rows without a full table scan. Lookups go from O(n) to O(log n).

Composite index order

Column order matters. An index on (a, b) serves queries on a and a + b, but not on b alone.

CREATE INDEX idx_posts_status_date ON posts(status, published_at);

When NOT to index

  • Tiny tables — the planner scans anyway.
  • Columns written constantly — index maintenance costs writes.
  • Low-cardinality columns alone (like a boolean).
Index the WHERE clause first, then JOIN and ORDER BY columns.

Always verify with EXPLAIN before and after. Numbers beat intuition.
